#### FIND-20261123-004

- **title:** SQLBI shows TEXTCONTAINS on a full-text index at compatibility level 1708
- **claim:** SQLBI’s 16 Nov 2026 article says Power BI semantic models can build a full-text index on string columns, a feature introduced in preview in September 2026. `TEXTCONTAINS` checks whether text matches the search, and `TEXTSIMILARITY` returns a relevance score. The column property `fullTextIndexingBehavior` requires compatibility level 1708 or higher and applies only to string columns in Import, Dual, or Direct Lake. `Full` builds the index on every process, `Explicit` builds it only on an indexes refresh through the XMLA endpoint, and `Off` makes `TEXTCONTAINS` or `TEXTSIMILARITY` return an error. The article says `Auto` is not supported for this property. The index increases memory use and refresh time.
- **why_it_matters:** Power BI portfolio — a text search that should match words rather than character spans needs a full-text index on a 1708 model, and leaving the property off makes those two functions fail

#### FIND-20261123-006

- **title:** PyPI agent-framework 1.26.1 and 1.26.2 were a credential stealer; 1.26.0 is the safe pin
- **claim:** Wiz Research reports that at 20:35 UTC on 17 Nov 2026 a malicious `agent-framework` 1.26.1 was uploaded to PyPI, and that 1.26.2 followed at about 21:08 UTC. As of about 21:30 UTC the same day, both versions were no longer available on PyPI. The page names 1.26.0 as the most recent safe version. Installed malicious builds drop a `.pth` file that Python runs on every interpreter start, so the stealer runs even when `agent-framework` is never imported. Version 1.26.1 uses `agent_framework_meta.pth`. Version 1.26.2 uses `af_runtime_diag.pth` instead, so a search for only the 1.26.1 file names misses it. Wiz says it reported the findings to Microsoft on 17 Nov and updated the write-up on 18 Nov at 14:00 UTC. A read of the PyPI project JSON during this run still lists 1.26.0 as the latest version and has no files for 1.26.1 or 1.26.2.
- **why_it_matters:** field-card — an environment that installed agent-framework 1.26.1 or 1.26.2 should be treated as having run a credential stealer on Python startup; pin to 1.26.0 and do not treat those two versions as upstream releases

#### FIND-20261123-007

- **title:** Pydantic AI Harness 0.70.0 fixes two high event-loop stalls in secret redaction and ANSI stripping
- **claim:** GitHub advisory GHSA-5m5q-5qj4-gx9h, published 18 Nov 2026, rates as high a quadratic-time `jwt` pattern in Pydantic AI Harness secret redaction. Affected versions are `pydantic-ai-harness` 0.16.0 through 0.69.0. The pattern is included by default in `redact_secrets` and `secret_data()`. Crafted text of a few hundred kilobytes can occupy the event loop for tens of seconds to minutes. The patched version is 0.70.0. Until then, the advisory says to leave `jwt` out by naming the patterns you need. The same 0.70.0 line fixes GHSA-m4cr-m4qc-9hh3, also high and published 18 Nov 2026: with `strip_ansi=True` (named `OverflowingToolOutput` before 0.13.0), ANSI stripping could take quadratic time. That advisory’s affected range is 0.4.0 through 0.69.0, and it says to leave `strip_ansi` at its default `False` until the upgrade. These are the harness fixes shipped with pydantic-ai v2.70.0. They do not replace the 4 Nov advisory set already gathered.
- **why_it_matters:** field-card — a harness still on 0.69.0 or earlier can stall the event loop on attacker-controlled text when default JWT redaction is on, or when `strip_ansi=True`; 0.70.0 is the patched line
