# Pydantic AI 2.58.0 — MCP tokens in traces; UI adapters could skip the model

## Why open

pydantic-ai `v2.58.0` (release title 19 Oct 2026; GitHub published 2026-10-20T04:58:32Z; MIT; still active) fixes two medium advisories. **GHSA-xv4x-g8mx-ch56:** provider-native MCP configuration could expose server URLs, authorization tokens, and custom header values in OpenTelemetry request traces even with `include_content=False`. A URL-based MCP capability could also expose a credential embedded in the URL-derived identifier. The note says to restrict access to historical traces and rotate exposed credentials. The same telemetry fix is in **v1.107.8**. With Temporal tracing enabled, URL-based MCP activity names stay unchanged so in-flight workflows keep their names; after those workflows complete, pass an explicit `id=` to `MCP`. **GHSA-5pfm-2g3g-gh85:** with non-empty server-side `message_history` and `manage_system_prompt='server'` (the default), Vercel AI and AG-UI adapters could execute an available tool with client-chosen arguments without a model request. Approval-required tools are not on that path. v1 is unaffected by the adapter issue. This is the trace and adapter fix. It does not move the ApprovalReviewer watch on [SIG-20261019-001](./SIG-20261019-001.md) or the Python 3.11 floor on [SIG-20261012-001](./SIG-20261012-001.md). Named consumer: field-card. GitHub/OSS filters pass (named consumer, upgrade-and-rotate decision, primary release notes, MIT + activity). Default path: signal — upgrade and rotate this month. It is not a durable prefer/avoid floor, and it does not change the github-mcp-server pin.

## Watch for

- A named consumer still below 2.58.0 that traces MCP calls — upgrade, treat historical traces as credential-bearing, and rotate exposed MCP tokens
- A v1 worker — telemetry fix is v1.107.8; the adapter issue does not apply to v1
- AG-UI or Vercel adapters on the default server-managed prompt with non-empty server-side history — do not stay below 2.58.0; approval-required tools were outside this path
- Temporal tracing — keep the existing URL-based activity id until in-flight workflows finish, then set an explicit `id=`
- Promote a prefer/avoid knowledge note only if field-card adopts a floor and the trace/adapter contract holds; else expire
- Leave SIG-20261019-001 and SIG-20261012-001 on their own contracts
