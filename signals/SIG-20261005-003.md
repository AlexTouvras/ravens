# ApproximateDistinctCount on Import and Direct Lake — keep an exact distinct-count switch

## Why open

Chris Webb’s 4 Oct 2026 post (blog.crossjoin.co.uk) says Import and Direct Lake semantic models now support `ApproximateDistinctCount()`, which previously applied to DirectQuery. On one Direct Lake model (1.4 billion-row NYC Taxi fact), a distinct count of Total Amount by Date took about 6 seconds, about 82 seconds of CPU, and 206,294 KB; the approximate count took about 4 seconds and about 48 seconds of CPU, with higher memory (1,063,476 KB). He reports those approximate values about **1.6%** from the actuals on that test, and that stakeholders who need exact figures will reject the error. His workaround is a field parameter that defaults to the approximate count and lets the reader switch to an exact distinct count. The Microsoft Learn function page was not available this run, so this stays a practitioner report, not a Learn pin. Named consumer: Power BI portfolio. Do not replace the Direct Lake prefer rule or treat 1.6% as a guaranteed error bound.

## Watch for

- A Microsoft Learn function page that documents `ApproximateDistinctCount` on Import and Direct Lake — then consider a knowledge note with an explicit exact-path limit
- A portfolio board where high-cardinality distinct counts are the slow query: try the approximate measure only with a visible exact switch
- Financial totals and low-cardinality categories stay `DISTINCTCOUNT`
- Expire if Learn does not corroborate and no board tries the switch this window
