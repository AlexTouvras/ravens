# Pydantic AI 2.57.0 — ApprovalReviewer can clear low-risk tool calls before a person

## Why open

pydantic-ai `v2.57.0` (release title 15 Oct 2026; GitHub published 2026-10-16T03:35:35Z; MIT; still active) adds a harness `ApprovalReviewer` that lets a model approve low-risk tool calls before a person sees them. The linked pull request shows the capability is attached with `ApprovalReviewer(model, question=..., tools=...)`. On a tool that already requires approval, a reviewer answer of `no` approves the call in the same run step; `yes`, `unsure`, a model failure, or a run budget that cannot fit the review leaves the call for the person. The reviewer never denies a call and does nothing for calls that do not need approval. The same release forwards MCP Apps tool results to AG-UI and Vercel AI frontends and adds `MCPToolset.read_resource_contents`. This is an approval-path capability on top of the open Python 3.11 floor in [SIG-20261012-001](./SIG-20261012-001.md). That floor and the stable durable `run_id` stay as they are. Named consumer: field-card. GitHub/OSS filters pass (named consumer, whether to attach model pre-approval, primary release notes, MIT + activity). Default path: signal — evaluate this month rather than a durable prefer/avoid pin.

## Watch for

- A named consumer on 2.57.0 — attach `ApprovalReviewer` only when a model clearing low-risk approvals is an explicit choice; re-test the human gate before adopting the pin
- A `no` answer runs the call before a person sees it; every other reviewer outcome still waits for a person
- A follow-on that enables the reviewer without an explicit harness attachment, or that lets the reviewer deny calls
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the opt-in pre-approval contract holds; else expire
- Leave the Python 3.11 floor on SIG-20261012-001
