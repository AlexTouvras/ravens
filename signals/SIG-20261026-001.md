# DAX Lib MCP 0.2.0 can return package functions in a query without writing the model

## Why open

`daxlib/daxlib-mcp` **v0.2.0** (GitHub release published 2026-11-01T18:41:48Z; MIT; still active) adds `get_function_definitions`. It returns a DAX query DEFINE block with the selected functions of a package and the functions they call, including functions from dependency packages at the versions that package declares, and it reports any function it cannot add. Those functions can be used in a query without changing the model. `install_package` warns when the installed package depends on a package that is not in the model. The 0.1.0 install path from Marco Russo’s SQLBI post of 22 Oct 2026 still holds underneath: the server can write a package’s original functions into a Power BI Desktop model open on the same computer; a function of the same name is replaced; the file is not saved; the install tool is marked as changing data. Limits on that page, which 0.2.0 does not lift: **Windows x64 only**, the model must already be open in Desktop, and the model needs compatibility level **1702** or higher. Omitting a version can still pull a prerelease. Named consumer: Power BI portfolio. GitHub/OSS filters pass (named consumer, query-versus-write decision, primary release notes, MIT + activity). Default path: signal — try the query path this month. It does not replace the compat-1702 UDF rule, the calculation-contract rule, or the hosted-vs-local authoring-MCP choice.

## Watch for

- A query that should carry package functions without writing them into the open model — use `get_function_definitions`, and read any function the tool says it cannot add
- An `install_package` warning that a dependency package is missing from the model
- A portfolio model on Windows Desktop at compat 1702+ where an install would still replace a same-named function — read the approval, then save in Desktop
- A macOS or closed-model workflow — the 0.1.0 install path does not run there
- An unspecified package version — that path can pull a prerelease
- Promote a prefer/avoid note only if the portfolio adopts the server and the query-without-write plus overwrite / no-save limits still hold; else expire
- Leave [dax-udfs-ga-compat-1702](../knowledge/data-bi/dax-udfs-ga-compat-1702.md), [dax-contract-before-ai-measure](../knowledge/data-bi/dax-contract-before-ai-measure.md), and [powerbi-authoring-mcp-hosted-vs-local](../knowledge/data-bi/powerbi-authoring-mcp-hosted-vs-local.md) as they stand
