# Pydantic AI 2.55.0 — Python 3.11 floor; stable durable run id

## Why open

pydantic-ai `v2.55.0` (GitHub release published 2026-10-09T19:20:25Z; MIT; still active) requires **Python 3.11 or newer in every package**. Python 3.10 installs resolve to **2.54.0 and earlier**. The same cut records tool requests from `ExaSearch`, `YouSearch`, `LocalStack`, and other harness capabilities under durable execution, and **keeps the default `run_id` and `conversation_id` stable** when a durable run is re-executed. That is an install floor and a durable-execution identity rule on top of the 2.54.0 compatibility release. It does **not** reopen expired [SIG-20260831-002](./SIG-20260831-002.md) (2.36.0 durable-execution backend; later 2.x polish, no named-consumer adoption). Named consumer: field-card. GitHub/OSS filters pass (named consumer, interpreter and run-identity decision, primary release notes, MIT + activity). Default path: signal — evaluate this month rather than a durable prefer/avoid pin.

## Watch for

- A named consumer pinning 2.55.0 — require Python 3.11+ first; a 3.10 environment will not pick up this release
- Durable re-runs that assumed a new default `run_id` or `conversation_id` — those ids now stay stable
- A follow-on that drops the 3.11 floor or mints a new default run id on re-execution
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the 3.11 / stable-id contract holds; else expire
