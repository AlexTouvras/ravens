# PyPI agent-framework 1.26.1 and 1.26.2 were a credential stealer; stay on 1.26.0

## Why open

Wiz Research reports that at 20:35 UTC on 17 Nov 2026 a malicious `agent-framework` 1.26.1 was uploaded to PyPI, and that 1.26.2 followed at about 21:08 UTC. As of about 21:30 UTC the same day, both versions were no longer available on PyPI. The page names 1.26.0 as the most recent safe version. Installed malicious builds drop a `.pth` file that Python runs on every interpreter start, so the stealer runs even when `agent-framework` is never imported. Version 1.26.1 uses `agent_framework_meta.pth`. Version 1.26.2 uses `af_runtime_diag.pth` instead, so a search for only the 1.26.1 file names misses it. Wiz says it reported the findings to Microsoft on 17 Nov and updated the write-up on 18 Nov at 14:00 UTC. A read of the PyPI project JSON on this run still lists 1.26.0 as the latest version and has no files for 1.26.1 or 1.26.2. Named consumer: field-card. This is a supply-chain check, not a pin bump. It does not raise [SIG-20260908-001](./SIG-20260908-001.md). That signal stays on 1.26.0. Default path: signal — check environments this week. It is not a durable prefer/avoid rule beyond the pin that signal already holds.

## Watch for

- A lockfile, image, or virtualenv that installed `agent-framework` 1.26.1 or 1.26.2 — treat Python startup in that environment as having run the stealer, then pin 1.26.0
- `agent_framework_meta.pth` (1.26.1) or `af_runtime_diag.pth` (1.26.2) under site-packages
- Do not raise the evaluate pin on SIG-20260908-001 to 1.26.1 or 1.26.2
- Expire on 7 Dec 2026 if no named-consumer environment installed those versions
- Leave the github-mcp pin unchanged
