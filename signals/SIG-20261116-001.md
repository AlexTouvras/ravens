# Pydantic AI 2.68.0 asks for approvals inside the run and falls back when max_tokens cuts the response

## Why open

pydantic-ai `v2.68.0` (release title 11 Nov 2026; GitHub published 2026-11-12T01:56:19Z; MIT; still active) adds `RequestInput` so a run can ask for approvals and answers inside the run, puts `AskUser` on the deferred pipeline, and marks deferred calls with `kind` and `answered_by`. The same release adds `OutputTokenLimitExceeded` and falls back to the next model in `ModelFallback` when a response is cut off at `max_tokens`. It also requires workspace backends to leave detached processes running. The prior tag in the compare is v2.67.0, published the same week, and is not a separate finding. This is the in-run approval and fallback change after the 4 Nov schema advisory patched in 2.66.0. It does not reopen the expired ApprovalReviewer watch ([SIG-20261019-001](./SIG-20261019-001.md)). It does not change the schema-expansion watch ([SIG-20261109-003](./SIG-20261109-003.md)). It does not reopen the expired trace and adapter watch ([SIG-20261026-003](./SIG-20261026-003.md)). Named consumer: field-card. GitHub/OSS filters pass (named consumer, approval-and-fallback decision, primary release notes, MIT + activity). Default path: signal — evaluate this month. It is not a durable prefer/avoid rule.

## Watch for

- A worker on 2.68.0 that should collect an approval or an answer inside the run — that path is `RequestInput`, with `AskUser` on the deferred pipeline
- A `ModelFallback` chain where a response cut off at `max_tokens` should move to the next model, via `OutputTokenLimitExceeded`
- A workspace backend that kills detached processes — 2.68.0 requires those processes to keep running
- Promote a prefer/avoid note only if field-card adopts 2.68.0 and the in-run approval plus the max_tokens fallback still hold; else expire
- Do not fold this into the Agent Framework pin ([SIG-20260908-001](./SIG-20260908-001.md))
