# Microsoft Agent Framework Python 1.25.0 — Python 3.11 required; MCP discovery caps

## Why open

microsoft/agent-framework `python-1.25.0` (GitHub release published 2026-11-07T15:52:42Z; MIT; still active) is the install and discovery break after 1.24.0. It removes Python 3.10 installation eligibility and requires Python 3.11 or later. That is the removal the 30 Oct release said the next release would make. Existing integration-specific upper bounds still apply; Foundry Local supports Python 3.11–3.14. The same release bounds MCP tool and prompt discovery to 100 pages and 1,000 items per catalog, defaults framework-owned request timeouts to 30 seconds, and keeps the previous catalog snapshot when a refresh fails. Raise `max_discovery_pages` or `max_discovery_items` for a larger catalog, or set either to `None` only for a trusted MCP server. Pass `request_timeout=None` on an MCP tool to restore unlimited request timing. Caller-owned clients keep their own transport and timeout policy. Live workflow executors and their sessions are bound to one authorization scope, and cross-scope reuse is rejected before a model call (`WORKFLOW_SCOPE_CONFLICT`). `WorkflowAgent.as_tool()` is rejected in AG-UI endpoints (`WORKFLOW_AGENT_TOOL_UNSUPPORTED`). Declarative workflows open and close a fresh MCP protocol session for every handler call, including `tools/list`, instead of caching an initialized session. The release notes mark that session fix as shipping in declarative 1.5.0. The legacy `cache_max_size` parameter is accepted as a deprecated no-op. The 1.24.0 rules still hold underneath: Python 3.11 was already the supported baseline; local MCP tools outside the per-tool lists take an explicit default approval mode; a beta Redis context index from before 1.24.0 has to be deleted and re-ingested, because `overwrite_index=True` does not migrate it. The 1.23.0 rules still hold under that: MCP 2.x transports, errors, schemas, and lifecycle; an AG-UI endpoint will not register until the process declares an explicit authorization scope or a single-user mode; Docker shell `extra_run_args` is `unsafe_extra_run_args`. The 1.22.0 persisted-state rules still hold under that: pre-1.22 runtimes cannot read new `hosted` or `merge_mode` records. Do not mix old and new workers on the same affected store. Anyone cloning the pin should land on **1.25.0**, not exact 1.24.0, and should leave Python 3.10 behind before installing. Named consumer: field-card. GitHub/OSS filters pass (named consumer, install and discovery decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule. Same pin — no second SIG.

## Watch for

- A named consumer moving a worker to 1.25.0 — Python 3.10 cannot install this release; upgrade the interpreter to 3.11 or later first
- A large MCP catalog stops at 100 pages or 1,000 items unless those limits are raised; `None` is only for a trusted server
- Framework-owned MCP request timeouts default to 30 seconds; a failed refresh keeps the previous catalog snapshot
- A shared live workflow executor or session cannot be reused across authorization scopes; the rejection happens before a model call
- Declarative MCP handlers no longer keep an initialized session across calls; `cache_max_size` does not restore that cache
- Keep the explicit local MCP approval default, rebuild a legacy Redis context index, and keep pre-1.22 workers off a store that holds new `hosted` or `merge_mode` records
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the Python 3.11 install floor plus the discovery caps still hold; else expire
