# Microsoft Agent Framework Python 1.19.0 — explicit HTTP cookies, ZIP-only MCP archives, per-invocation MCP sessions

## Why open

microsoft/agent-framework `python-1.19.0` (GitHub release published 18 Sep 2026; MIT; still active) is the first 1.19 pin after 1.18.0 that changes MCP cookie, skill-archive, and session-scope defaults: HTTP cookie persistence becomes **explicit** for framework-owned and caller-owned clients; MCP skill archives are limited to **ZIP** files and the MCP sampling callback is deprecated; provider-backed MCP sessions are scoped **per invocation**. The same cut adds generic vector-store provider protocols, alpha MongoDB / Azure DocumentDB / Cosmos NoSQL connectors, stable names plus checkpoint-type registration for built-in orchestration workflows, sequential function-call invocation, and tighter security-label / owned-input enforcement. It does **not** reopen the 1.18.0 `SecretString` wrapper, Lab-off-`core[all]`, or Foundry-checkpoint-allowlist contracts, nor the 1.17.0 sequence-only middleware / removed `agent-hooks` contract. Anyone cloning the pin should land on **1.19.0**, not exact 1.18.0. Named consumer: field-card. GitHub/OSS filters pass (named consumer, cookie/archive/session decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule.

## Watch for

- A named consumer cloning or documenting the 1.19.0 path — do not assume cookies persist by default, `.mcp` archives install, or provider MCP sessions survive across invocations; keep SecretString as a masked wrapper, Lab off `core[all]`, middleware sequence-only, and drop `agent-hooks`
- A follow-on 1.19.x / 1.20 that restores implicit cookie persistence, non-ZIP skill archives, or cross-invocation MCP sessions
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the 1.19.0 contract holds; else expire
