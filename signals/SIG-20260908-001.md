# Microsoft Agent Framework Python 1.21.0 — tool-agent session isolation; full-buffer Purview

## Why open

microsoft/agent-framework `python-1.21.0` (GitHub release published 2026-10-08T10:27:26Z; MIT; still active) is the first cut after 1.20.0 that changes the session contract again: it **isolates provider-owned service session state when agents are invoked as tools**, adds tool-result standing guidance, exposes rewritten variable-expansion arguments, and supports **full-buffer Purview policy evaluation for streamed responses**. DevUI scopes function approvals to their conversations. The 1.20.0 rules still hold underneath: unresolved approval bindings and agent-tool approvals **fail closed**, local file access stays **session-scoped**, and Foundry hosting stays on the breaking request-scoped factory / sandbox-isolated session path. The 1.19.0 rules still hold under that: HTTP cookie persistence stays **explicit**, MCP skill archives stay **ZIP-only**, and provider-backed MCP sessions stay **per invocation**. It does **not** reopen the 1.18.0 `SecretString` wrapper, Lab-off-`core[all]`, or Foundry-checkpoint-allowlist contracts, nor the 1.17.0 sequence-only middleware / removed `agent-hooks` contract. Anyone cloning the pin should land on **1.21.0**, not exact 1.20.0. Named consumer: field-card. GitHub/OSS filters pass (named consumer, session-isolation decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule. Same pin — no second SIG.

## Watch for

- A named consumer cloning or documenting the 1.21.0 path — a tool-agent does not share the caller’s provider service session; streamed responses can be Purview-evaluated on the full buffer; unresolved tool approvals still fail closed; isolate local file access per session; do not assume cookies persist by default, `.mcp` archives install, or provider MCP sessions survive across invocations
- Keep SecretString as a masked wrapper, Lab off `core[all]`, middleware sequence-only, and drop `agent-hooks`
- A follow-on that shares tool-agent service sessions with the caller, restores fail-open approvals, implicit cookie persistence, non-ZIP skill archives, or cross-invocation MCP sessions
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the 1.21.0 session contract holds; else expire
