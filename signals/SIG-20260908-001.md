# Microsoft Agent Framework Python 1.26.0 — Copilot CLI 1.0.85 and a 30-second Hyperlight budget

## Why open

microsoft/agent-framework `python-1.26.0` (GitHub release published 2026-11-13T08:28:16Z; MIT; still active) is the runtime break after 1.25.0. It requires GitHub Copilot CLI 1.0.85 or later and fails startup when that version is older or cannot be determined. A custom runtime selected by `cli_path`, `GITHUB_COPILOT_CLI_PATH`, or `COPILOT_CLI_PATH` has to be upgraded to CLI 1.0.85 or later. Default SDK installations already meet this minimum: the existing SDK floor, 1.0.16, bundles CLI 1.0.90. The GitHub Copilot integration in this release is 2.2.0. The same release interrupts cancelled Hyperlight guest execution and applies a finite 30-second execution budget by default. Guest execution requires an SDK that provides `Sandbox.interrupt_handle()`, documented for Hyperlight SDK 0.9.0 or later. Installation still permits SDK 0.8.0 and does not add a fallback for older SDKs. A larger positive finite `execution_timeout_seconds` can be set on `HyperlightCodeActProvider` or `HyperlightExecuteCodeTool`. Timeouts return error content. Caller cancellation propagates `asyncio.CancelledError`. Runtime initialization and host callbacks cannot be interrupted. The release deprecates the legacy experimental `MemoryContextProvider`, `MemoryFileStore`, `MemoryStore`, `MemoryIndexEntry`, and `MemoryTopicRecord` APIs for removal after 31 Dec 2026. Existing imports and saved memories remain supported. Using the classes, or subclassing `MemoryStore`, emits deprecation warnings. The replacement is `FileMemoryProvider` with an `AgentFileStore`, such as `FileSystemAgentFileStore`. That store uses a different layout, does not migrate existing files, and does not extract memories or provide transcript history. The default scope is the session. The 1.25.0 rules still hold underneath: Python 3.10 cannot install; Python 3.11 or later is required; MCP discovery is bounded to 100 pages and 1,000 items; framework-owned request timeouts default to 30 seconds; a failed refresh keeps the previous catalog snapshot; live workflow executors and sessions are bound to one authorization scope; declarative handlers open a fresh MCP session per call. The 1.24.0 approval-mode and Redis-index rules, the 1.23.0 MCP 2.x / AG-UI registration rules, and the 1.22.0 persisted-state rules still hold under that. Anyone cloning the pin should land on **1.26.0**, not exact 1.25.0. PyPI versions 1.26.1 and 1.26.2 were not upstream releases. They were a credential stealer and are no longer on PyPI. Stay on 1.26.0. The environment check is [SIG-20261123-004](./SIG-20261123-004.md). Named consumer: field-card. GitHub/OSS filters pass (named consumer, runtime-pin decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule. Same pin — no second SIG.

## Watch for

- A named consumer moving a worker to 1.26.0 — a custom Copilot CLI below 1.0.85 will not start; default SDK installs already bundle CLI 1.0.90
- A Hyperlight guest now stops at 30 seconds unless `execution_timeout_seconds` is raised; interruption needs Hyperlight SDK 0.9.0 or later. Install still allows 0.8.0 and does not fall back
- Legacy experimental memory classes warn now and are scheduled for removal after 31 Dec 2026; `FileMemoryProvider` does not migrate existing files
- Keep the 1.25.0 Python 3.11 install floor, the MCP discovery caps, and the one-scope workflow session rule
- Keep pre-1.22 workers off a store that holds new `hosted` or `merge_mode` records
- Do not raise this pin to 1.26.1 or 1.26.2 — those versions were a credential stealer ([SIG-20261123-004](./SIG-20261123-004.md))
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the CLI floor, the 30-second Hyperlight budget, and the Python 3.11 floor still hold; else expire
