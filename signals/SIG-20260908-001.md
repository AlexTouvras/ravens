# Microsoft Agent Framework Python 1.23.0 — MCP 2.x lifecycle and explicit AG-UI auth

## Why open

microsoft/agent-framework `python-1.23.0` (GitHub release published 2026-10-22T17:05:37Z; MIT; still active) is the MCP and AG-UI registration break after 1.22.0. It adds an MCP 2.x compatibility foundation and migrates MCP transports, errors, schemas, and lifecycle handling. An AG-UI endpoint will not register until the process declares an explicit authorization scope or a single-user mode. Docker shell `extra_run_args` is renamed `unsafe_extra_run_args`. The same cut separates caller-owned and framework-owned MCP client lifecycles. The 1.22.0 persisted-state rules still hold underneath: persisted artifacts containing serialized `Content` or streamed response-update records are not safely shared across versions; the 1.22 runtime can read older records, but pre-1.22 runtimes cannot read new records containing `hosted` or `merge_mode`. Do not run old and new workers against the same affected store, and do not downgrade after 1.22 has written those records unless the new state is isolated or migrated. The 1.21.0 rules still hold under that: tool-agent calls **isolate provider-owned service session state**, streamed responses can take **full-buffer Purview** evaluation, unresolved approval bindings **fail closed**, and local file access stays **session-scoped**. The 1.19.0 rules still hold under that: HTTP cookie persistence stays **explicit**, MCP skill archives stay **ZIP-only**, and provider-backed MCP sessions stay **per invocation**. Anyone cloning the pin should land on **1.23.0**, not exact 1.22.0, declare AG-UI auth or single-user mode before registering an endpoint, and keep pre-1.22 workers off an affected store. Named consumer: field-card. GitHub/OSS filters pass (named consumer, MCP-lifecycle and AG-UI registration decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule. Same pin — no second SIG.

## Watch for

- A named consumer moving a worker to 1.23.0 — previous MCP client lifecycle no longer matches, and an AG-UI endpoint stays unregistered until an authorization scope or single-user declaration is set
- Docker shell callers still passing `extra_run_args` — the argument name is `unsafe_extra_run_args`
- Keep pre-1.22 workers off a store that holds new `hosted` or `merge_mode` records; plain session metadata without serialized messages stays shareable
- Keep tool-agent provider sessions isolated, unresolved approvals fail-closed, cookies explicit, and MCP skill archives ZIP-only
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the MCP 2.x / AG-UI auth contract holds; else expire
