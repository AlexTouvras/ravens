# Microsoft Agent Framework Python 1.17.0 — sequence-only middleware; agent-hooks extra removed

## Why open

microsoft/agent-framework `python-1.17.0` (GitHub release published 3 Sep 2026; MIT; still active) is a breaking pin on `agent-framework-core` and `agent-framework-foundry`: it restores sequence-only agent middleware inputs and removes the experimental `agent-hooks` core extra. The same cut adds Foundry-hosted Agent Server vs agent-owned model-history selection (to prevent duplicated conversation replay), documents a same-event-loop concurrency contract for shared chat clients, supports OpenAI SDK 3.x while keeping existing floors, migrates Mistral chat/embedding clients to the official SDK, binds approvals to stable function-call occurrences, persists valid OAuth consent responses in Foundry hosting, and surfaces the underlying MCP initialization error when cancellation would otherwise mask a connection failure. Named consumer: field-card. GitHub/OSS filters pass (named consumer, middleware-contract decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule.

## Watch for

- A named consumer cloning or documenting the Foundry-hosted path — drop `agent-hooks` and treat middleware as sequence-only before that write-up
- A follow-on 1.17.x / 1.18 that restores `agent-hooks` or changes the middleware input shape again
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the sequence-only contract holds; else expire
