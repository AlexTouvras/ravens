# Microsoft Agent Framework Python 1.24.0 — Python 3.11 baseline and default MCP approval mode

## Why open

microsoft/agent-framework `python-1.24.0` (GitHub release published 2026-10-30T21:52:13Z; MIT; still active) is the support and approval change after 1.23.0. Python 3.11 or later is the supported baseline, subject to package-specific upper limits. Python 3.10 installation remains permitted by `Requires-Python` in this release, but compatibility is not guaranteed, and the next release will remove Python 3.10 from `Requires-Python`. The same release adds an explicit default approval mode for local MCP tools and prompts outside the per-tool approval lists, and warns when `never_require_approval` leaves that default implicit while preserving the existing fallback. The beta `RedisContextProvider` rejects the legacy raw-scope index. `overwrite_index=True` does not migrate an incompatible index, so the old index and its context hashes have to be deleted and the context re-ingested. The 1.23.0 rules still hold underneath: MCP 2.x transports, errors, schemas, and lifecycle; an AG-UI endpoint will not register until the process declares an explicit authorization scope or a single-user mode; Docker shell `extra_run_args` is `unsafe_extra_run_args`; caller-owned and framework-owned MCP client lifecycles stay separate. The 1.22.0 persisted-state rules still hold under that: persisted artifacts containing serialized `Content` or streamed response-update records are not safely shared across versions; the 1.22 runtime can read older records, but pre-1.22 runtimes cannot read new records containing `hosted` or `merge_mode`. Do not run old and new workers against the same affected store, and do not downgrade after 1.22 has written those records unless the new state is isolated or migrated. The 1.21.0 rules still hold under that: tool-agent calls **isolate provider-owned service session state**, streamed responses can take **full-buffer Purview** evaluation, unresolved approval bindings **fail closed**, and local file access stays **session-scoped**. The 1.19.0 rules still hold under that: HTTP cookie persistence stays **explicit**, MCP skill archives stay **ZIP-only**, and provider-backed MCP sessions stay **per invocation**. Anyone cloning the pin should land on **1.24.0**, not exact 1.23.0, treat Python 3.10 as unsupported, set the local MCP default approval mode explicitly, and rebuild a legacy Redis context index instead of overwriting it. Named consumer: field-card. GitHub/OSS filters pass (named consumer, support-baseline and approval-mode decision, primary release notes, MIT + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule. Same pin — no second SIG. This does not raise the Pydantic AI Python floor.

## Watch for

- A named consumer moving a worker to 1.24.0 — Python 3.10 is no longer a supported baseline, and local MCP tools outside the per-tool lists pick up the explicit default approval mode
- A beta Redis context index from before 1.24.0 — delete the old index and its context hashes and re-ingest; `overwrite_index=True` does not migrate it
- An AG-UI endpoint on 1.23.0+ stays unregistered until an authorization scope or single-user declaration is set; Docker shell callers pass `unsafe_extra_run_args`
- Keep pre-1.22 workers off a store that holds new `hosted` or `merge_mode` records; plain session metadata without serialized messages stays shareable
- Keep tool-agent provider sessions isolated, unresolved approvals fail-closed, cookies explicit, and MCP skill archives ZIP-only
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the Python 3.11 baseline plus the explicit MCP approval default still hold; else expire
