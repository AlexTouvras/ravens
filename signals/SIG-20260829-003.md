# Cursor Origin removes the GitHub prerequisite for starting a cloud agent

## Why open

Cursor's 27 Aug 2026 changelog says Cloud Agents no longer require a connected GitHub (or other third-party SCM) to get started: selecting "Start from scratch" in the repo picker lets an agent begin prompting immediately, with Cursor creating an Origin repo in the background; the work can later become a named Origin repo (private or internal visibility) via a "Create repo" button, and the cloud agent's live environment can now be port-forwarded to the browser for preview. This changes the bootstrap workflow for a brand-new prototype — a repo no longer has to exist on GitHub before an agent can start working. Similar to the now-expired [SIG-20260812-001](./SIG-20260812-001.md) (Cursor Automations product-surface churn), this is a fresh product capability rather than a settled adoption decision for ravens/ProjectBrain/JARVIS.

## Watch for

- Whether ravens, ProjectBrain, or JARVIS actually spins up a throwaway prototype via Origin before deciding to host it on GitHub
- Any durable "prefer Origin for X, GitHub for Y" rule emerging once Origin repos are used in practice
- Expire if no consumer adoption decision surfaces within the window
