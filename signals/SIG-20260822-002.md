# BRIDGEHEAD npm typosquat campaign bridges WSL into Windows for a crypto-wallet stealer

## Why open

CloudSEK's 20 Aug 2026 report describes "BRIDGEHEAD": 40 typosquatted npm packages (misspellings of chalk, axios, commander, lodash, react, typescript) published 16 Aug 2026, whose install script fingerprints Windows vs WSL-on-Windows and, if matched, downloads a native Windows Rust-based in-memory stealer targeting crypto wallets, Chromium credentials, cookies, and Telegram sessions — a payload the npm package itself never contains. Any Node/npm-based automation in the portfolio (ProjectBrain/JARVIS, careerops tooling, ravens' own `npm run verify`) should double-check exact dependency names before `npm install` and treat WSL-to-Windows install-script behavior as a live threat class distinct from the Aug-4 ChainDrop/Shai-Hulud wave.

## Watch for

- Whether any named consumer's `package.json` was ever exposed to one of the 40 typosquatted names (check dependency names, not just lockfile hashes)
- A durable prefer/avoid rule (e.g. lockfile-pinning, `npm audit`/registry-allowlist policy) emerging as standing guidance — promote to knowledge if so
- Further campaigns repeating the WSL-fingerprint technique, which would strengthen the case for a standing rule
- Expire if no named-consumer exposure and no durable policy change surfaces within the window
