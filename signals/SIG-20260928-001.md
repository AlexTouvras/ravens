# Cursor Rollouts and Security Review — Teams/Enterprise last-mile PR bots; no auto-merge

## Why open

Cursor’s changelog dated **23 Sep 2026** launches two bots on **Teams and Enterprise**, enabled from the automations tab. **Rollouts** attaches a monitor to every pull request, writes an editable monitoring plan as a PR comment, wakes on deploy events, and reports per-environment health as verified healthy, regression detected, or inconclusive; on a regression it can open a revert PR for review or hand the finding to a cloud agent, but it **does not merge or roll back on its own today**. **Security Review** reads every pull request in codebase context (**draft PRs skipped**), posts one review comment for exploitable bugs (injection, authz bypasses including checks a refactor stopped running, secrets committed to source, SSRF, unsafe deserialization, known-vulnerable dependency changes), and leaves style/quality to Bugbot. This is the first changelog pin after the 10 Sep Projects coordinator ([SIG-20260911-001](./SIG-20260911-001.md), now expired) — not a skills-vs-rules change and not a data-handling rule for the security hub. Named consumers: field-card (HITL last-mile) and ravens (already on cron-plus-push, not Rollouts deploy monitors). Product-surface landing; HITL / enablement rules have not settled.

## Watch for

- A named consumer actually enabling Rollouts or Security Review on Teams/Enterprise
- Explicit field-card guidance: treat deploy health or secret-in-PR review as automatic vs still HITL (Rollouts will not merge or roll back alone)
- Auto-merge / auto-rollback, or Security Review folding into Bugbot, which would change the gate
- Expire if no consumer enablement or HITL rule surfaces this window; do not fold into the expired Projects coordinator watch
