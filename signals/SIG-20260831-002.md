# Pydantic AI 2.36.0 — public durable-execution backend API and named @durable_operation

## Why open

Pydantic AI v2.36.0 (GitHub release published 29 Aug 2026; tagged 28 Aug 2026; MIT) adds `@durable_operation` for capabilities plus a **public backend API** so third-party durable execution engines can plug in, and a follow-on change in the same release **requires an explicit operation name** on `@durable_operation` (bare decorator is a TypeError) so persisted durable-unit names stay stable across method renames. The release also adds `--mcp-config` support and tool-call streaming to the `clai` CLI. Durable agent state is an explicit watchlist seam for field-card / ProjectBrain / JARVIS — this is a clone-vs-build and "which durability engine can we attach" decision, not yet a prefer/avoid rule.

## Watch for

- A named consumer actually wiring Temporal / Prefect / DBOS (or equivalent) through the new public backend — then promote a pin ("require an explicit `@durable_operation` name; do not use the bare decorator")
- Whether the backend API stays stable across a follow-on minor, or churns enough to stay signal-only
- Expire if no consumer evaluates the release this month and no durable prefer/avoid rule emerges
