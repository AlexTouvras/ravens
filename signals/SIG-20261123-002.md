# TEXTCONTAINS needs a full-text index at compatibility level 1708

## Why open

SQLBI’s article of 16 Nov 2026 says Power BI semantic models can build a full-text index on string columns. The feature was introduced in preview in September 2026 and is still in preview. `TEXTCONTAINS` checks whether text matches the search. `TEXTSIMILARITY` returns a relevance score. The column property `fullTextIndexingBehavior` requires compatibility level 1708 or higher and applies only to string columns in Import, Dual, or Direct Lake. `Full` builds the index every time the table is processed. `Explicit` builds it only when an indexes refresh is triggered through the XMLA endpoint. `Off` makes `TEXTCONTAINS` or `TEXTSIMILARITY` return an error. `Auto` is not supported for this property. The index increases memory use and refresh time. No Power BI visual uses the index yet; the filter pane still searches characters. Named consumer: Power BI portfolio. Practitioner source, preview feature — signal, not a calculation-contract change. It does not replace the compat-1702 UDF rule or the calculation-contract rule.

## Watch for

- A word search that should not match character spans — the column needs `fullTextIndexingBehavior` at compat 1708, and `Off` makes the two functions fail
- `Auto` on this property — it is not a supported value
- The feature leaving preview, or a visual that starts using the index — that is the bar before a knowledge note
- Expire on 7 Dec 2026 if the portfolio has not tried it and the preview limits are unchanged
- Leave [dax-udfs-ga-compat-1702](../knowledge/data-bi/dax-udfs-ga-compat-1702.md) and [dax-contract-before-ai-measure](../knowledge/data-bi/dax-contract-before-ai-measure.md) as they stand
