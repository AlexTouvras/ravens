# microsoft/skills-for-fabric 0.3.16 — single-skill APM install; Azure CLI reuse for remote MCP

## Why open

microsoft/skills-for-fabric `v0.3.15` (GitHub release published 6 Sep 2026; changelog dated 4 Sep 2026; MIT) is the first Fabric skill-pack cut since the 0.3.14 weekly maintenance pin that changes a clone-vs-wire choice this month. It adds `onelake-catalog-govern-cli` and a read-only Capacity Metrics workflow in `skills/sqldw-cli`. `v0.3.16` (published 10 Sep 2026) is the first later cut that changes the install/auth flow: a root `apm.yml` plus a generated `skills/<name>/apm.yml` for every skill so a user can install **one skill** with `apm install microsoft/skills-for-fabric --skill <name>` instead of the whole plugin bundle; the same notes document the APM bootstrap and the scope difference between Copilot CLI (`-g`, `~/.copilot/mcp-config.json`) and VS Code (project `.vscode/mcp.json`). The `fabric-skills` plugin now reuses **Azure CLI sign-in** for remote MCP in local Claude Code, with matching Codex configuration and guidance for older registrations, without copying access tokens or registering another OAuth application. Anyone cloning the pack should land on **0.3.16**, not exact 0.3.15. Named consumer: Power BI portfolio / Orbit Analytics. GitHub/OSS filters pass (named consumer, clone-vs-wire, primary release notes, MIT + activity). Default path: signal — evaluate the pack this month rather than a durable prefer/avoid pin.

## Watch for

- A named consumer cloning or wiring **0.3.16+** — pull one skill via APM instead of the whole bundle, reuse Azure CLI for remote MCP rather than a second OAuth app, and use the OneLake catalog-governance / Capacity Metrics workflows instead of custom glue
- A follow-on 0.3.x that retracts single-skill APM install, Azure CLI reuse, or either 0.3.15 workflow
- Expire if no consumer evaluates the release this month and no durable prefer/avoid rule emerges
