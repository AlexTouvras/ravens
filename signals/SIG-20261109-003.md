# Pydantic AI 2.46–2.65 expands a crafted tool schema without a bound

## Why open

GHSA-484x-x9m4-62cj (published 2026-11-04T11:51:40Z; CVSS 3.1 score 6.5) says `pydantic-ai` and `pydantic-ai-slim` from 2.46.0 through 2.65.0 expand a tool argument schema by resolving every `$ref` again at each place it appears. A small schema whose definitions reference one another repeatedly takes exponential time and memory on the event loop. Tools whose schemas a client can supply reach this code, most directly an AG-UI endpoint. From 2.50.0 every request expands every offered tool. From 2.46.0 through 2.49.x only `TypeSafeModel` did, and only for the tool the model selected. One crafted schema can block the event loop for minutes and exhaust process memory. The advisory says the assumed attacker is an authenticated client of that endpoint. Patched in **2.66.0**. Until then, drop or limit client-submitted tools, for example by rejecting schemas that contain `$defs`. Named consumer: field-card. This is the schema-expansion advisory. It does not change the MCP-trace and adapter watch on [SIG-20261026-003](./SIG-20261026-003.md), and it does not reopen the expired ApprovalReviewer watch ([SIG-20261019-001](./SIG-20261019-001.md)). Default path: signal — upgrade this month. It does not change the github-mcp-server pin.

## Watch for

- An AG-UI worker on pydantic-ai 2.46.0 through 2.65.0 that accepts client-supplied tool schemas — move to 2.66.0, or reject schemas that contain `$defs` until that upgrade
- A worker below 2.50.0 still hits this when it uses `TypeSafeModel` on a client-selected tool
- Promote a prefer/avoid floor only if field-card adopts 2.66.0+ and the client-schema limit still holds; else expire
- Leave SIG-20261026-003 on the trace and adapter contract, and leave the github-mcp pin unchanged
