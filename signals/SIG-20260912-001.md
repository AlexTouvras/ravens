# Google ADK Python 2.9.0 — FallbackModel failover, YAML graphs, MCP 2.x opt-in; failed nodes re-run on resume

## Why open

google/adk-python `v2.9.0` (GitHub release published 10 Sep 2026; Apache-2.0; still active) is the first 2.9 cut after 2.8.0. It adds `FallbackModel` automatic failover when the primary model errors, a LiveKit runner for voice/telephony agents, declarative ADK 2.0 graphs loadable from YAML, and compatibility with MCP SDK 2.x while default installs still resolve MCP 1.x (2.x is an opt-in). Breaking changes: a failed workflow node now runs again on resume instead of replaying as complete (node bodies that already performed an external side effect must be idempotent); GCS tools read and write local files only inside `local_file_root` and refuse local access when that setting is absent; `InMemorySessionService` now raises `SessionNotFoundError` when appending to a session it does not hold. Nested-workflow retry and MCP 2.x unknown-field discard apply only when `retry_config` is set or MCP 2.x is installed deliberately. Named consumer: field-card. GitHub/OSS filters pass (named consumer, resume/GCS/MCP decision, primary release notes, Apache-2.0 + activity). Default path: signal — evaluate / pin this month rather than a durable prefer/avoid rule.

## Watch for

- A named consumer cloning or documenting ADK Python — treat failed-node resume as a re-run (idempotent node bodies), confine GCS local paths to `local_file_root`, and keep MCP 1.x unless you deliberately opt into 2.x
- A follow-on 2.9.x / 2.10 that restores replay-as-complete, changes the GCS root rule, or makes MCP 2.x the default resolve
- Promote a prefer/avoid knowledge note only if field-card adopts the pin and the 2.9.0 resume / GCS / MCP contract holds; else expire
